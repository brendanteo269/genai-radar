GenAI Radar

Brendan Teo · November 2026 · heineken-radar-project.vercel.app · github.com/brendanteo269/genai-radar

Why I built this

I read about HEINEKEN’s Global GenAI Lab in Singapore and the tools it builds for staff, and I wanted to try my hand at building something that could be useful to a team like that.

The problem I picked is a simple one. There is a new AI tool every week, and every announcement says it changes everything. If you work in sales or finance at a brewery, you do not have an hour to work out which ones are real. So I built a page that reads the announcements every morning and gives a straight answer on each one: what it is, who should care, and whether it is worth trying this week.

What it does

Each morning it reads the announcement feeds from OpenAI, Google, Microsoft, SAP, Salesforce, Meta, Mistral, The Verge and Zapier. Microsoft and SAP are there because they are the AI suppliers HEINEKEN is publicly reported to use. Most of what comes through is not a tool at all. It is news, or funding, or something only developers can use. Those get thrown out.

What is left gets one short card. The card says what the tool does in a sentence, which team it suits (brand and marketing, sales, supply chain and brewery, finance, or internal comms and HR), one real task to try it on, and a verdict: try now, watch, or skip. It also names the catch, including what company data you should keep out of it.

The part I care about most

Three things. Everything is sourced: every card links back to the original announcement, so nobody has to take the card’s word for it. It stays current: it runs daily and only looks at the last seven days. And it is targeted: every card names the team it is for, so a sales rep does not have to read finance tools to find theirs.

One honest limit: every card is auto-graded. Claude read the announcement, and nobody used the tool. The page says so on every card.

What the first run taught me

The first real run read 20 announcements and produced 2 cards. That looked bad, and my first guess was that the grading was too strict.

So I went through the 16 it rejected, one by one. Fifteen were plainly not tools: news stories, a research talk, developer plumbing. Only one was a fair argument. The grading was fine. The sources were the problem, because news feeds mostly carry news. I added a feed of actual product release notes and left the rules alone.

How it works, for the technical reader

There are four parts. n8n runs the workflow, Claude does the grading, GitHub stores the result, and Vercel serves the page.

The n8n workflow has 16 nodes and two ways in: a timer at 8am Singapore time, and a form where you paste one link to grade it on demand. It reads the feeds, keeps anything from the last seven days, and skips links it has already handled.

Each remaining item goes to Claude Haiku in its own HTTP call. The prompt is one file, prompt.md, and it holds the five audiences and the grading rules. Claude has to answer in a fixed JSON shape or say the item is not relevant. Pointing the radar at a different company would mean editing that one file.

The cards are saved as a single file, cards.json, which the workflow commits to GitHub. The page is one static HTML file with no framework and no chart library. Every commit redeploys it.

How I kept it reliable

Nothing half-done gets saved. If Claude’s reply is missing a field, invents a verdict, or the call fails, the item is counted and dropped. That happened to 2 of the 20 in the first run.

Failures get retried on their own. A link is only marked as seen after a clean answer, and that list lives in the same file as the cards. So a bad run fixes itself the next morning without me touching it.

One news site blocks automated readers. I dropped it instead of working around the block.

The code inside each n8n node lives in its own file, and a small script runs each one outside n8n against the awkward cases. It copies one n8n quirk I found the hard way: the code sandbox has no URL parser.

Where it is weak

It runs on my laptop, so when the laptop is off nothing updates. Twelve feeds is a sample and not the whole market. Anthropic has no feed at all, so Claude news has to go in through the form. Most cards so far come from a one-off backfill of the last two months, which I graded in Claude Code against the same rules, not from the daily run. And it is not a data policy. It reminds people what to keep out of a tool, but it cannot decide that for a company.
